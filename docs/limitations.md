# Limitations

## Version 1 limitations

- Events are generated by simulated sources rather than production CI/CD integrations.
- Correlation rules identify likely relationships, not proven causality.
- An incident can have only one primary correlation grouping in version 1.
- The deterministic classifier covers a finite catalogue of demonstration failure types.
- Provider-generated text can still be incomplete or misleading despite validation; human review remains mandatory.
- Historical similarity does not prove that a previous resolution is appropriate.
- Log search is designed for portfolio-scale datasets, not petabyte-scale observability workloads.
- PostgreSQL is a single logical system of record; high-availability and multi-region recovery are outside scope.
- Application-level tenant isolation is implemented before optional database row-level security.
- Version 1 does not execute rollback, restart, scaling, credential, deployment, or infrastructure changes.
- Evaluation data is synthetic and therefore does not establish production model performance.
- Acceptance rate alone is not treated as proof of recommendation quality.

## Responsible interpretation

Recommendations are diagnostic hypotheses supported by cited evidence. Confidence represents the system's calibrated assessment under its configured rules and provider, not a guarantee. An abstention indicates that the available evidence does not justify a useful conclusion and should be treated as correct safety behaviour rather than a platform failure.
